# 검증 기록

> SlopLens는 AI 슬롭을 판정하는 절대 기준이 아닙니다. 아래는 "지금 이 도구를 어디까지 믿어도 되는가"를 정직하게 기록한 것입니다.
> 개인 프로젝트와 특정 제작자의 작업은 이름을 밝히지 않고 그룹으로만 적습니다. 원자료(스크린샷·리포트)는 공개하지 않습니다.

## 요약

| 층 | 지금 믿을 수 있는 정도 | 근거 |
|---|---|---|
| 웹사이트 · 측정만 | 1차 선별용으로 유효 | 처음 보는 10개(AI 5 / 사람 5) AUC 1.00. 표본이 작고 비교가 쉬운 편이라 구간이 넓다 |
| 게임 · 측정만 | **AI 여부 판별에 쓸 수 없음** | 새 표본 10개에서 AUC 0.48 → 리뷰 없으면 "판정 보류"로 표시 |
| 지각 리뷰 (확정 판정의 65%) | **정확도 미검증** | 지금까지의 리뷰는 정답을 아는 리뷰어(개발 중인 AI)가 작성 |
| 설명·해결책 | 근거는 확인 가능, 효과는 미검증 | 모든 지적이 화면·측정값에 묶여 있지만, 고친 뒤 사람이 덜 슬롭으로 느끼는지는 아직 재지 않음 |

## 1. 처음 보는 대상으로 잰 정확도 (v0.4)

규칙을 조정하기 전에 대상을 먼저 정하고 측정했다. 라벨은 "슬롭인가"가 아니라 **누가 만들었나**다.

| 그룹 | 출처 | 고른 방법 |
|---|---|---|
| AI 사이트 5 | AI 빌더 해커톤 공개 갤러리 (AI 빌더 사용 필수) | 갤러리 한 페이지를 순서대로. 접속 불가면 다음 순서 |
| AI 게임 5 (+2차 5) | AI 코딩 게임잼 공개 목록 (코드 80~90%+ AI 작성 필수) | 공개 API 632개에서 고정 시드로 무작위 추출 |
| 사람 사이트 5 | GOV.UK, GitHub, Airbnb, Mozilla, 개인 인터랙티브 블로그 | 조정에 한 번도 쓰지 않은 사이트 |
| 사람 게임 5 (+2차 5) | 2013~2017년(LLM 이전) 웹게임 (2048, A Dark Room, HexGL, Little Alchemy 2, Candy Box 2 등) | 측정 불가(봇 차단·인증서 오류)는 교체 |

**측정만 (조정 전 첫 측정)**

| 구분 | AUC (90% 구간) | 기준선 40 정확도 | 평균 AI / 사람 |
|---|---|---|---|
| 웹 | 1.00 (1.00–1.00) | 100% | 50.9 / 11.0 |
| 게임 | 0.48 (0.16–0.80) | 50% — 사람 게임 5개 모두 오판 | 56.1 / 56.1 |

**게임 측정의 원인 수정 후**

| 세트 | 성격 | AUC |
|---|---|---|
| 1차 게임 10개 | 원인을 진단한 세트 | 0.48 → 0.72 |
| **2차 게임 10개** | **수정 후 처음 본 세트** | **0.48** |

측정이 잡는 "마감 결함"(효과음 없음, 일시정지 없음, 도형 그래픽, 난이도 곡선 없음)은 사람이 만든 잼·취미 게임에도 똑같이 있다.
그래서 **리뷰 없는 게임은 점수와 관계없이 "판정 보류 (지각 리뷰 필요)"**로 표시하고, 점수는 마감 결함의 양으로만 설명한다.

**지각 리뷰 반영** (측정값을 보기 전에 화면만 보고 리뷰했지만, 리뷰어가 제작 주체를 알고 있었음)

| 구분 | 기준선 정확도 | 평균 AI / 사람 |
|---|---|---|
| 웹 | 10/10 | 62.9 / 3.9 |
| 게임 | 9/10 | 63.2 / 11.0 |

- 이 숫자는 부풀려져 있다. 라벨을 모르는 사람 평가자와 비교해야 리뷰의 실제 정확도를 말할 수 있다.
- 놓친 1개는 AI로 만들었지만 화면 완성도가 높은 게임이었다. **"AI가 만들었다"와 "슬롭으로 느껴진다"는 같지 않다.**

## 2. 이 과정에서 찾아 고친 문제

**게임 측정**
- 자동 플레이가 시작 메뉴를 못 넘었는데 "반응 없음·피드백 없음·소리 없음"을 결함으로 셌다 → 도달하지 못하면 "측정 안 됨"
- 화면 변화 감지가 `<canvas>`만 봤다 → DOM 게임(타일 퍼즐·방치형·텍스트)도 화면 전체 비교
- 액션 게임 기준(타격감·일시정지·난이도 곡선·rAF 루프)을 턴제·방치형에도 적용 → 실시간 캔버스 게임에만 적용
- "효과음 없음"을 두 규칙이 이중으로 셈 → 한 번만

**측정 인프라**
- 봇 차단 페이지(Cloudflare)를 작품으로 판정 → "측정 불가"로 멈춤
- 429 응답 재시도, 리다이렉트 중 측정 실패, 윈도우 경로 길이 초과 수정

**이미지 판정 (v0.4.1)**
- "AI 생성 이미지를 생성기 출력 그대로 썼나"를 별도로 판정하는 규칙(ART-03/04)과 리뷰 항목 S9 추가
- 직선이 강한 이미지(제품 배너·파이프 스프라이트·미로 화면)를 가짜 픽셀아트로 오인 → 격자 칸 수·색 수 조건 추가
- 광고 이미지의 AI 생성 표기를 작품 것으로 판정 → 다른 도메인 이미지 제외
- 웹 페이지의 사진·일러스트 묶음을 "스타일 혼재 세트"로 판정 → 웹은 세트로 보지 않음

**문구·배색 (v0.3.1)**
- 큰 기업 페이지의 마케팅 문구 한 줄로 "상투 태그라인" 판정 → 웹은 여러 번 반복될 때만
- 제품 기능명 "Todo"를 개발용 문구로 판정 → 대문자 `TODO`만
- 의도된 2색 단색 브랜드 배색을 "AI 청록 시네마틱"으로 판정 → 단색 브랜드 배경 제외
- 마케팅 CTA("~해 보세요")를 설명 과잉으로 판정 → 웹은 조작 안내만 집계

## 3. 지각 우선 구조로 바꾼 이유 (v0.3)

v0.2는 코드의 AI 기본값 패턴을 셌다. 실제로 돌려 보니 결과가 반대로 나왔다.
- 제작자가 명백한 AI 슬롭으로 보는 비공개 게임 3개는 낮은 점수를 받았다.
- 누가 봐도 공들인 Stripe는 가장 높은 점수를 받았다(AI가 흉내 내는 원본이라 패턴이 겹침).

그래서 화면·소리를 직접 보는 지각 리뷰를 판정의 중심에 두고, 측정은 근거로 돌렸다.
같은 비공개 게임 3개는 리뷰 반영 후 65~73점(AI 슬롭)이 되었고, Stripe는 13점(의도가 보이는 결과물)이 되었다. 단, 리뷰어가 제작자의 판단을 미리 알고 있었다.

## 4. 남은 과제 — 신뢰도를 숫자로 말하려면

1. **사람 평가 기준 데이터**: 30~50개 작품을 3명 이상이 제작 주체를 모른 채 "슬롭으로 느껴지는 정도"로 평가한다. 평가자 간 일치도와 도구·사람 간 일치도를 잰다.
2. **어려운 비교군**: 사람이 만든 흔한 템플릿 사이트·소상공인 사이트, 사람이 만든 게임잼 작품
3. **해결책 효과**: 해결책을 적용하기 전과 후의 화면을 평가자에게 보여 주고 실제로 덜 슬롭으로 느끼는지 확인한다
4. **반복 측정 안정성**: 같은 대상의 점수 흔들림 폭(현재 일부 사이트에서 ±2~4점)
5. 게임 사운드는 스크린샷으로 판단할 수 없고, FMOD 출력은 아직 녹음하지 못한다
